# 유저 스토리 & 유저 시나리오 (User Stories & Scenarios)

**구성 방식**: 페르소나 기반 + 유저 여정 기반 하이브리드
**범위**: MVP 전체 (요구사항 정의서 기준)
**수용 기준 형식**: Given-When-Then + 체크리스트 혼합
**INVEST 기준 준수**: Independent, Negotiable, Valuable, Estimable, Small, Testable

# Part A. 고객 페르소나 (김지은) — 유저 스토리

## 유저 여정 (User Journey) — 내러티브

> 점심시간, 김지은은 동료 3명과 식당에 들어와 4번 테이블에 앉는다. 테이블에 놓인 태블릿에는 이미 메뉴 화면이 떠 있다(직원이 미리 세팅해 자동 로그인된 상태). 지은은 별도 로그인 없이 바로 카테고리 탭을 눌러 '메인 메뉴'를 살펴보고, 음식 사진과 설명을 확인하며 김치찌개와 불고기를 장바구니에 담는다. 동료들의 메뉴까지 추가한 뒤 장바구니에서 수량을 조정하고 총액을 확인한 다음 '주문하기'를 누른다. 주문번호가 화면에 표시되고 5초 뒤 메뉴 화면으로 돌아간다. 식사 중 음료가 필요해지자 다시 사이다를 주문하고, '주문내역' 탭에서 지금까지의 주문과 총액을 확인한다.

---

## US-C1: 테이블 자동 로그인
**As a** 고객(김지은), **I want** 테이블 태블릿에서 별도 로그인 없이 바로 주문 화면을 사용하기를, **so that** 직원을 부르거나 절차를 거치지 않고 즉시 주문할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 관리자가 테이블 태블릿을 초기 설정하여 로그인 정보가 로컬에 저장되어 있고,
  **When** 고객이 태블릿 화면을 사용할 때,
  **Then** 저장된 정보로 자동 로그인되어 메뉴 화면이 표시된다.
- **Given** 유효한 활성 세션이 없을 때,
  **When** 태블릿이 로드되면,
  **Then** 새로운 테이블 세션이 생성된다.

**체크리스트**
- [ ] 메뉴 화면이 기본(홈) 화면으로 표시된다
- [ ] 자동 로그인 시 세션 ID가 확보된다
- [ ] 잘못된 비밀번호로는 로그인되지 않는다

**관련 요구사항**: FR-1.1

---

## US-C2: 카테고리별 메뉴 조회
**As a** 고객, **I want** 카테고리별로 분류된 메뉴를 사진·설명·가격과 함께 보기를, **so that** 어떤 음식인지 쉽게 파악하고 선택할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 매장에 등록된 메뉴가 있을 때,
  **When** 고객이 메뉴 화면에 진입하면,
  **Then** 카테고리별로 그룹화된 메뉴가 카드 형태로 표시된다.
- **Given** 여러 카테고리가 존재할 때,
  **When** 고객이 카테고리 탭을 누르면,
  **Then** 해당 카테고리 섹션으로 빠르게 이동한다.

**체크리스트**
- [ ] 각 메뉴 카드에 메뉴명, 가격, 설명, 이미지가 표시된다
- [ ] 카테고리 탭으로 빠른 이동이 가능하다
- [ ] 터치 타겟이 최소 44x44px 이상이다
- [ ] 판매 불가(is_available=0) 메뉴는 표시되지 않는다

**관련 요구사항**: FR-1.2

---

## US-C3: 장바구니 관리
**As a** 고객, **I want** 선택한 메뉴를 장바구니에 담고 수량을 조절하기를, **so that** 주문 전에 원하는 구성과 금액을 확인할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 고객이 메뉴를 선택할 때,
  **When** 메뉴 카드의 추가 버튼을 누르면,
  **Then** 해당 메뉴가 장바구니에 담기고 수량 배지가 갱신된다.
- **Given** 장바구니에 메뉴가 담겨 있을 때,
  **When** 수량을 증가/감소하거나 삭제하면,
  **Then** 총 금액이 실시간으로 재계산된다.
- **Given** 장바구니에 항목이 있을 때,
  **When** 페이지를 새로고침하면,
  **Then** 장바구니 내용이 그대로 유지된다.

**체크리스트**
- [ ] 메뉴 추가/삭제가 가능하다
- [ ] 수량 증가/감소가 가능하다 (0이 되면 항목 제거)
- [ ] 총 금액이 실시간 계산된다
- [ ] 장바구니가 로컬에 저장되어 새로고침 시 유지된다
- [ ] 서버 전송은 주문 확정 시에만 이루어진다

**관련 요구사항**: FR-1.3

---

## US-C4: 주문 생성
**As a** 고객, **I want** 장바구니의 메뉴를 주문으로 확정하기를, **so that** 주방에 내 주문이 전달되고 음식을 받을 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 장바구니에 1개 이상의 메뉴가 있을 때,
  **When** 고객이 '주문하기'를 누르면,
  **Then** 주문이 생성되고 주문번호가 화면에 표시된다.
- **Given** 주문이 성공적으로 생성되었을 때,
  **When** 주문 성공 화면이 표시되면,
  **Then** 장바구니가 자동으로 비워지고 5초 후 메뉴 화면으로 리다이렉트된다.
- **Given** 주문 전송이 실패할 때,
  **When** 서버 오류가 발생하면,
  **Then** 에러 메시지가 표시되고 장바구니는 그대로 유지된다.

**체크리스트**
- [ ] 주문 정보에 매장 ID, 테이블 ID, 메뉴 목록(명/수량/단가), 총액, 세션 ID가 포함된다
- [ ] 주문 성공 시 주문번호 표시 → 장바구니 비우기 → 5초 후 메뉴 리다이렉트
- [ ] 주문 실패 시 에러 메시지 + 장바구니 유지
- [ ] 유효하지 않은 세션으로는 주문이 거부된다

**관련 요구사항**: FR-1.4

---

## US-C5: 현재 세션 주문 내역 조회
**As a** 고객, **I want** 현재 식사 세션의 주문 내역과 상태를 확인하기를, **so that** 내가 무엇을 주문했고 얼마인지, 음식이 어디까지 진행됐는지 알 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 현재 세션에 주문이 존재할 때,
  **When** 고객이 '주문내역' 탭을 열면,
  **Then** 주문이 시간 역순으로 표시된다.
- **Given** 이전 세션(이용 완료된)의 주문이 있을 때,
  **When** 주문 내역을 조회하면,
  **Then** 현재 세션의 주문만 표시되고 과거 세션 주문은 제외된다.

**체크리스트**
- [ ] 주문별 주문번호, 시각, 메뉴/수량, 금액, 상태(대기중/준비중/완료)가 표시된다
- [ ] 현재 테이블 세션의 주문만 표시된다
- [ ] 매장 이용 완료된 주문은 제외된다

**관련 요구사항**: FR-1.5

# Part B. 관리자 페르소나 (박상철) — 유저 스토리

## 유저 여정 (User Journey) — 내러티브

> 저녁 피크 타임, 박상철 사장은 카운터 PC에서 관리자 대시보드에 로그인한다(아침에 한 번 로그인하면 16시간 유지되어 다시 로그인할 필요가 없다). 화면에는 테이블별 카드가 그리드로 배열되어 있고, 4번 테이블에 새 주문이 들어오자 카드가 강조 색상으로 깜빡이며 즉시 표시된다. 상철은 카드를 눌러 전체 주문 메뉴를 확인하고 상태를 '준비중'으로 바꾼다. 음식이 나가면 '완료'로 변경한다. 한 손님이 메뉴를 잘못 눌러 주문한 항목은 삭제 버튼으로 제거하고, 총 주문액이 자동 재계산되는 것을 확인한다. 손님이 식사를 마치고 나가면 해당 테이블을 '이용 완료' 처리하여 주문 내역을 과거 이력으로 넘기고 테이블을 초기화한다. 영업 종료 후에는 '과거 내역'에서 그날의 주문을 확인한다.

---

## US-A1: 매장 인증 (16시간 세션)
**As a** 관리자(박상철), **I want** 매장 식별자와 계정으로 로그인하고 세션이 16시간 유지되기를, **so that** 영업 중 반복 로그인 없이 시스템을 사용할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 유효한 매장 식별자/사용자명/비밀번호가 입력될 때,
  **When** 관리자가 로그인하면,
  **Then** JWT 토큰이 발급되고 16시간 세션이 시작된다.
- **Given** 유효한 세션이 존재할 때,
  **When** 브라우저를 새로고침하면,
  **Then** 세션이 유지되어 다시 로그인할 필요가 없다.
- **Given** 16시간이 경과했을 때,
  **When** 관리자가 보호된 기능에 접근하면,
  **Then** 자동 로그아웃되어 재로그인을 요구한다.

**체크리스트**
- [ ] JWT 토큰 기반 인증
- [ ] 16시간 세션 유지 및 만료 후 자동 로그아웃
- [ ] 새로고침 시 세션 유지

**관련 요구사항**: FR-2.1

---

## US-A2: 실시간 주문 모니터링
**As a** 관리자, **I want** 들어오는 주문을 테이블별 그리드에서 실시간으로 확인하기를, **so that** 피크 타임에도 주문을 누락 없이 처리할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 관리자 대시보드가 열려 있을 때,
  **When** 고객이 새 주문을 생성하면,
  **Then** 2초 이내에 해당 테이블 카드에 주문이 표시된다(SSE).
- **Given** 새 주문이 도착할 때,
  **When** 대시보드에 반영되면,
  **Then** 해당 카드가 시각적으로 강조(색상/애니메이션)된다.
- **Given** 테이블 카드를 볼 때,
  **When** 카드를 클릭하면,
  **Then** 전체 주문 메뉴 목록 상세가 표시된다.

**체크리스트**
- [ ] SSE 기반 실시간 통신으로 2초 이내 표시
- [ ] 테이블별 카드 그리드 레이아웃
- [ ] 각 카드에 총 주문액, 최신 주문 미리보기 표시
- [ ] 신규 주문 시각적 강조
- [ ] 테이블별 필터링 기능

**관련 요구사항**: FR-2.2, NFR-1

---

## US-A3: 주문 상태 변경
**As a** 관리자/직원, **I want** 주문 상태를 대기중→준비중→완료로 변경하기를, **so that** 고객과 직원이 음식 진행 상황을 알 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 주문이 존재할 때,
  **When** 관리자가 상태를 변경하면,
  **Then** 주문 상태가 갱신되고 고객 주문 내역에도 반영된다.
- **Given** 유효하지 않은 상태 값이 전달될 때,
  **When** 상태 변경을 요청하면,
  **Then** 요청이 거부된다(pending/preparing/completed만 허용).

**체크리스트**
- [ ] 상태는 대기중/준비중/완료 3단계
- [ ] 잘못된 상태 값 거부
- [ ] 존재하지 않는 주문에 대한 변경은 404 처리

**관련 요구사항**: FR-2.2

---

## US-A4: 주문 삭제 (직권 수정)
**As a** 관리자, **I want** 잘못된 주문을 삭제하기를, **so that** 오주문을 정정하고 정확한 총액을 유지할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 특정 주문이 존재할 때,
  **When** 관리자가 삭제 버튼을 누르고 확인 팝업에서 승인하면,
  **Then** 주문이 즉시 삭제되고 테이블 총 주문액이 재계산된다.

**체크리스트**
- [ ] 삭제 전 확인 팝업 표시
- [ ] 삭제 후 총 주문액 재계산
- [ ] 성공/실패 피드백 제공

**관련 요구사항**: FR-2.3 (주문 삭제)

---

## US-A5: 테이블 세션 종료 (이용 완료)
**As a** 관리자/직원, **I want** 손님이 떠난 테이블을 이용 완료 처리하기를, **so that** 새 손님이 이전 주문 없이 깨끗한 상태에서 시작할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 테이블에 활성 세션과 주문이 있을 때,
  **When** 관리자가 '이용 완료'를 확인 팝업에서 승인하면,
  **Then** 해당 세션의 주문이 과거 이력(OrderHistory)으로 이동한다.
- **Given** 이용 완료 처리가 완료될 때,
  **When** 테이블이 초기화되면,
  **Then** 현재 주문 목록과 총 주문액이 0으로 리셋되고 세션이 종료된다.
- **Given** 세션이 종료된 후,
  **When** 새 고객이 첫 주문을 시작하면,
  **Then** 새로운 세션이 시작된다.

**체크리스트**
- [ ] 확인 팝업 표시
- [ ] 세션 주문을 OrderHistory로 이동 (완료 시각 기록)
- [ ] 현재 주문/총액 0으로 리셋
- [ ] 세션 종료 및 새 세션 시작 가능
- [ ] 성공/실패 피드백

**관련 요구사항**: FR-2.3 (테이블 세션 처리)

---

## US-A6: 테이블 태블릿 초기 설정
**As a** 관리자/직원(이수민), **I want** 테이블 번호와 비밀번호를 설정하여 태블릿을 초기화하기를, **so that** 고객이 자동 로그인으로 바로 주문할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 새 테이블 태블릿을 세팅할 때,
  **When** 관리자가 테이블 번호와 비밀번호를 입력·저장하면,
  **Then** 16시간 세션이 생성되고 자동 로그인이 활성화된다.

**체크리스트**
- [ ] 테이블 번호 및 비밀번호 설정
- [ ] 세션 생성
- [ ] 설정 정보 저장 및 자동 로그인 활성화

**관련 요구사항**: FR-2.3 (초기 설정), FR-1.1

## US-A7: 과거 주문 내역 조회
**As a** 관리자, **I want** 테이블별 과거 주문 내역을 날짜로 필터링해 조회하기를, **so that** 영업 정산과 이력 확인을 할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 이용 완료된 세션의 주문 이력이 있을 때,
  **When** 관리자가 '과거 내역'을 열면,
  **Then** 테이블별 과거 주문이 시간 역순으로 표시된다.
- **Given** 과거 내역이 표시될 때,
  **When** 날짜 필터를 적용하면,
  **Then** 해당 날짜의 주문만 표시된다.

**체크리스트**
- [ ] 각 주문: 주문번호, 시각, 메뉴 목록, 총액, 이용 완료 시각 표시
- [ ] 시간 역순 정렬
- [ ] 날짜 필터링 기능
- [ ] '닫기'로 대시보드 복귀

**관련 요구사항**: FR-2.3 (과거 주문 내역 조회)

## US-A8: 메뉴 관리 (CRUD)
**As a** 관리자, **I want** 메뉴를 등록·수정·삭제하고 노출 순서를 조정하기를, **so that** 메뉴와 가격을 직접 최신 상태로 유지할 수 있다.

**수용 기준 (Given-When-Then)**
- **Given** 관리자가 메뉴를 등록할 때,
  **When** 메뉴명·가격·설명·카테고리·이미지를 입력하면,
  **Then** 필수 필드와 가격 범위 검증 후 메뉴가 저장된다.
- **Given** 기존 메뉴가 있을 때,
  **When** 관리자가 수정/삭제하면,
  **Then** 변경 사항이 고객 메뉴 화면에 반영된다.
- **Given** 여러 메뉴가 있을 때,
  **When** 노출 순서를 조정하면,
  **Then** 고객 화면의 메뉴 정렬 순서가 변경된다.

**체크리스트**
- [ ] 메뉴 등록/조회/수정/삭제
- [ ] 메뉴 정보: 메뉴명, 가격, 설명, 카테고리, 이미지(로컬 업로드)
- [ ] 노출 순서 조정
- [ ] 필수 필드 및 가격 범위 검증

**관련 요구사항**: FR-2.4
